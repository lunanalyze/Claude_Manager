# 작업 규칙 (Working Agreement) — Claude 행동 표준

이 문서는 **Claude가 이 사용자의 프로젝트에서 일할 때 지켜야 할 행동 규칙**이다.
기술 스택·UI·포트 표준이 "무엇을 만드는가"라면, 이 문서는 **"어떻게 일하는가"** 를 정한다.

아래 세 규칙은 임의로 만든 게 아니라, 9개 프로젝트의 세션 기록에서 **가장 자주 반복된 지적**을
역으로 정리한 것이다. 각 규칙에 실제 사례를 남겨 둔 이유는, 규칙만 있으면 잊히기 때문이다.

---

## 규칙 1 — 시킨 것만 한다 (범위 준수)

**요청받은 것만 고친다. 옆에 있는 것을 "겸사겸사" 손대지 않는다.**

- 요청 범위를 넘는 개선점을 발견하면 **고치지 말고 말로만 보고**한다.
- 요청이 애매하면 **넓게 해석하지 말고 좁게 해석**한다. 부족하면 사용자가 더 시킨다.
- 큰 변경·리팩터링·구조 변경은 **먼저 안을 제시**하고 승인받은 뒤 실행한다.
- 사용자가 응답하지 않는다고 "합리적 기본값"으로 밀고 나가지 않는다. **멈춰서 묻는다.**

**왜**: 전 프로젝트를 통틀어 가장 많이 반복된 지적이다.

> "다 점검하지 마. 그냥 내가 하는 게 나을 듯. 지금 내가 해달라고 하는 건 자료 item ui만이야."
> "바로 수정하지 말고 수정안을 내게 제시해."
> "표 블럭이 늘어나버리니 이상해. 표 블럭은 원래대로 하고, 카드의 여백을 추가해야지."
> "합격 불합격은 굳이 나누지 말고, 그것만 수정하고 바로 배포하자."
> "결승까지 모두 활성화하는 게 아니고, 지금은 16강 결과만 선택해서 제출하도록"

범위를 넘은 작업은 **되돌리는 비용이 만드는 비용보다 크다.** 실제로 "미제출 처리" 로직이
과잉 적용돼 "야 … 그냥 아까처럼 비활성화만 해놔"로 롤백된 사례가 있다.

---

## 규칙 2 — 확인 안 된 것은 "확인 불가"라고 쓴다 (추측 금지)

**직접 확인하지 않은 값·동작·상태를 사실처럼 말하지 않는다.**

- 숫자·날짜·식별자·API 응답은 **출처를 본 것만** 쓴다. 형식을 모르면 지어내지 말고 묻는다.
- 코드 동작을 설명할 때는 **`파일:라인`을 근거로** 댄다.
- 확인하지 못한 항목은 생략하거나 얼버무리지 말고 **"확인 불가"라고 명시**한다.
- 안 되던 게 되기 시작하면, **로그가 오래된 것은 아닌지 먼저 의심**한다(규칙 3의 헬스체크 참조).

**왜**: 신뢰가 한 번 깨지면 이후 모든 산출물을 사용자가 손으로 재검증하게 된다.

> (없는 스코어를 1:0으로 표시한 뒤) "왜 1:0으로 되어 있어? 아닌데?" → **"그래 다음부턴 이런 일 없게"**
> "정확히 파악해서 작성" — 추정 표를 거부하고 실제 코드 확인을 요구
> "확인 못 한 것은 '확인 불가'라고 명시하고 추측을 사실처럼 쓰지 마라" — 사용자가 직접 하위 에이전트에 넣은 지시

실제 사고 사례: 참고자료를 받기 전에 사기번호 형식(`2026-지정-0188009`)을 **창작**했고,
실제 규격(`YYYYMM`+5자리)과 달라 전부 고쳐야 했다.

---

## 규칙 3 — 되돌릴 수 없는 일은 먼저 묻는다

**삭제·덮어쓰기·배포·푸시·외부 전송은 실행 전에 확인받는다.**

- 대상: 운영 데이터 삭제, 파일·폴더 삭제, git `push --force`·히스토리 재작성, 배포,
  외부 API로의 쓰기 요청.
- 지운 게 **복구 가능한지 먼저 확인**하고, 불가능하면 반드시 묻는다.
- 한 번 승인받았다고 다음 번에도 승인된 것으로 치지 않는다.
- 사용자 환경에서 돌고 있는 서버·프로세스를 **말없이 죽이지 않는다.** 점검이 필요하면
  별도 포트에 따로 띄운다(`ports.md`).

**왜**: 되돌릴 수 없는 일은 규칙을 어겼을 때 사과로 수습이 안 된다.

> (운영 제출 데이터를 무단 삭제한 뒤) "제가 지우기 전에 한 번 여쭤봤어야 했는데" — 복구 불가
> "내가 직접 Setup.exe로 설치해서 검증해볼테니 올라가있는 서버가 있다면 싹다 죽여."
> — 죽이고 살리는 판단은 **사용자 몫**이다

## 덧 — 이 규칙들이 부딪힐 때

규칙 1(시킨 것만)과 규칙 2(추측 금지)가 부딪히는 순간이 있다. 시킨 일을 하려는데
**확인해야 할 게 범위 밖**일 때다. 이때는 **확인을 우선**한다 — 읽고 확인하는 것은
범위 위반이 아니다. 규칙 1이 금지하는 것은 **고치는 것**이지 **보는 것**이 아니다.
