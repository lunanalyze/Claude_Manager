# issue-log

한 번에 안 되어 **검증**했거나, **실패 후 해결**한 사례를 원자적 파일로 쌓는 **이슈 로그**다.
참고 문서(reference)와 다르다 — 이건 "무엇이 안 됐고 어떻게 뚫었나 + 다음엔 어떻게 피하나"의 기록이다.

폴더 `Claude_Manager/docs/issues/` 에 **한 이슈 = 한 파일**로 stack한다. 각 파일은 frontmatter에
`tags/stack/type`을 달아 **나중에 임베딩→RAG 검색이 가능하도록** 설계돼 있다(당장은 색인+grep 검색).

## 언제 쓰나
- 방금 작업이 **한 번에 안 되어** 검증하거나, **실패→해결**을 거쳤고, 사용자가 이를
  "이슈로 남겨/기록해둬/다음엔 이런 일 없게" 또는 "/issue-log" 로 요청할 때.
- Claude가 스스로 삽질을 인지했을 때, 기록을 **먼저 제안**해도 좋다("이 시행착오 이슈로 남길까요?").

## 먼저: 중복 확인
- 새로 쓰기 전에 `docs/issues/` 를 grep 해 **유사 이슈가 이미 있는지** 확인한다.
  있으면 새 파일 대신 그 파일을 **갱신**한다(중복 방지).

## 무엇을 기록하나 (핵심은 '재발 방지')
1. **무엇을 하려 했나** — 사용자의 요청/작업.
2. **무슨 일이 있었나** — 실패면 실제 에러·출력 발췌, 검증이면 무엇이 불확실했는지.
3. **원인** — 밝혀진 근본 원인(모르면 정황으로 솔직히).
4. **해결** — 실제로 통한 것. 실행한 명령/코드/설정을 **그대로**(출처 `파일:라인`).
5. **다음엔 이렇게** — 행동 가능한 재발 방지 규칙. *이게 이 문서의 존재 이유다.*
6. **검증 방법** — 해결됐는지 확인하는 법.

## 원칙
- **실제로 일어난 것만.** 에러 메시지·명령 출력·코드는 지어내지 말고 발췌한다.
- **행동 가능한 규칙으로 끝맺는다.** "조심하자"가 아니라 "X부터 확인, Y는 피하라, Z 환경은 A로".
- **검색 가능하게.** 제목은 증상 한 줄, frontmatter `tags`에 미래 세션이 칠 검색어를 넣는다.
- **환경/버전 특정성 명시.** WSL/Windows·패키지 버전에 의존하면 반드시 적는다(이 repo는 양 환경 공유).

## 저장 위치·형식
- 경로: `Claude_Manager/docs/issues/<slug>.md` (같은 폴더의 `TEMPLATE.md` 구조를 따른다).
- `<slug>`: 증상을 드러내는 영문 kebab-case (예: `wsl-jq-missing`, `next-image-remote-domain`).
- frontmatter 필수: `title, date, type(실패→해결|검증), status, stack, tags[]`.

## 색인 갱신
- `docs/issues/README.md` "목록"에 한 줄 포인터 추가:
  `- [제목](./<slug>.md) — 증상→해결 한 줄 · \`tag, tag\``.

## 보고
- 저장 경로, 재발 방지 규칙 한 줄, 태그를 사용자에게 요약해 전달한다.

## 설계 메모
- 단일 원본은 `Claude_Manager/skills/issue-log/`, 각 환경 `~/.claude/skills/`에 심링크로 설치.
- 생성물(이슈 파일)은 `docs/`(git 추적)라 WSL/Windows가 clone으로 공유한다.
- **재활용 흐름**: 위험하거나 낯선 작업 전, 세션은 `docs/issues/`를 먼저 검색해 기존 사례를 참고한다.
  (추후 이 폴더를 임베딩해 RAG로 자동 주입하도록 확장 가능 — 원자적 파일+메타데이터가 그 전제.)
