# issue-log

한 번에 안 되어 **검증**했거나 **실패 후 해결**한 사례를 원자적 파일로 쌓는 **이슈 로그**다.
참고 문서(`../references/`)와 다르다 — "무엇이 안 됐고 어떻게 뚫었나 + 다음엔 어떻게 피하나"의 기록이다.

폴더 `Claude_Manager/docs/issues/` 에 **한 이슈 = 한 파일**로 stack한다. 각 파일 frontmatter의
`tags/stack/type`은 **추후 임베딩→RAG 검색**을 위한 것이다(당장은 색인 + `grep`).

---

## 모드 선택

호출 인자·표현으로 두 모드 중 하나를 고른다.

### 모드 A — 지정 기록 (기본)
사용자가 **특정 사례를 짚어** 기록을 요청할 때. ("이거 이슈로 남겨", "방금 삽질 정리해둬", `/issue-log`)
→ 현재 대화/작업 맥락에서 그 한 건을 뽑아 **이슈 파일 1개**를 쓴다. 아래 [기록 절차]로 진행.

### 모드 B — 전체 스윕 (`sweep` / "transcript 다 뒤져서" / "이슈 전부 찾아")
프로젝트 transcript를 훑어 **발생했던 이슈들을 소급 백필**할 때. 대량 작업이므로 아래 순서를 따른다.

1. **대상 transcript 위치 파악**: 이 프로젝트의 세션 로그는 `~/.claude/projects/<slug>/*.jsonl`.
   `slug`는 cwd 경로 기반이다. 같은 repo의 `transcript-to-md` skill이 위치·파싱을 이미 안다 —
   읽기 쉬운 형태가 필요하면 그 파서로 md 변환 후 훑어도 된다.
2. **후보 좁히기 (싼 패스 먼저)**: 전 세션을 통째로 읽지 말고, 실패·검증 신호부터 grep으로 건진다.
   ```bash
   grep -rlniE "error|failed|not found|command not found|traceback|denied|eaddrinuse|✗|다시|안 ?돼|왜 안|실패|그게 아니" ~/.claude/projects/<slug>/*.jsonl
   ```
   신호가 걸린 세션·구간만 실제로 읽는다.
3. **에피소드 판별**: 각 후보에서 "요청 → (실패/불확실) → 해결/검증" 흐름이 **재사용 가치가 있는지**
   판단한다. 일회성 잡음(오타 즉시정정 등)은 제외, **다시 만날 만한 것**만 기록한다.
4. **분량이 크면 팬아웃**: 세션이 많으면 세션(또는 구간)별로 서브에이전트(Task/Explore)를 병렬로
   돌려 후보 에피소드를 요약해 오게 하고, 취합해 기록한다.
5. 각 확정 에피소드를 [기록 절차]로 **파일 1개씩** 남긴다. 끝에 **스윕 요약**(훑은 세션 수, 찾은
   이슈 수, 목록, 건너뛴 이유)을 사용자에게 보고한다.

> 스윕은 토큰을 많이 쓴다. 범위가 넓으면 먼저 "N개 세션에서 후보 M건 —— 기록할까요?"로 확인하고 진행한다.

## 기록 절차 (두 모드 공통)

### 1) 중복 확인
새 파일 전에 `docs/issues/` 를 grep 해 **유사 이슈가 있는지** 본다. 있으면 새로 만들지 말고 **갱신**한다.
```bash
grep -rin "<키워드>" docs/issues/
```

### 2) 무엇을 담나 (핵심은 '재발 방지')
1. **무엇을 하려 했나** — 요청/작업.
2. **무슨 일이 있었나** — 실패면 실제 에러·출력 발췌, 검증이면 무엇이 불확실했는지.
3. **원인** — 근본 원인(모르면 정황으로 솔직히).
4. **해결** — 실제로 통한 명령/코드/설정을 그대로(출처 `파일:라인`). 스스로 풀었는지/사용자 지시였는지도.
5. **다음엔 이렇게** — 행동 가능한 재발 방지 규칙. *이 문서의 존재 이유.*
6. **검증 방법** — 해결 확인법.

### 3) 원칙
- **실제로 일어난 것만.** 에러·명령·코드는 지어내지 말고 transcript/파일에서 발췌.
- **행동 가능한 규칙으로 끝맺기.** "조심하자"가 아니라 "X부터 확인, Y는 피하고 Z로".
- **검색 가능하게.** 제목은 증상 한 줄, frontmatter `tags`에 미래 세션이 칠 검색어.
- **환경/버전 특정성 명시** (WSL/Windows·패키지 버전 — 이 repo는 양 환경 공유).

### 4) 저장·형식
- 경로: `Claude_Manager/docs/issues/<slug>.md` (같은 폴더 `TEMPLATE.md` 구조).
- `<slug>`: 증상을 드러내는 영문 kebab-case (예: `wsl-jq-missing`, `next-image-remote-domain`).
- frontmatter 필수: `title, date, type(실패→해결|검증), status, stack, tags[]`.

### 5) 색인 갱신
`docs/issues/README.md` "목록"에 한 줄 추가: `- [제목](./<slug>.md) — 증상→해결 한 줄 · \`tag, tag\``.

### 6) 보고
저장 경로, 재발 방지 규칙 한 줄, 태그를 요약해 전달(스윕은 전체 요약 포함).

## 설계 메모
- 단일 원본 `Claude_Manager/skills/issue-log/`, 각 환경 `~/.claude/skills/`에 심링크 설치.
- 생성물(이슈 파일)은 `docs/`(git 추적)라 WSL/Windows가 clone으로 공유.
- transcript(생성 로그)는 git 미포함이며 환경마다 로컬이다 → **스윕은 각 환경에서 그 환경 로그를 대상으로** 돈다.
- 재활용: 위험·낯선 작업 전 세션은 `docs/issues/`를 먼저 검색한다. (추후 임베딩 RAG로 자동 주입 확장 가능.)
