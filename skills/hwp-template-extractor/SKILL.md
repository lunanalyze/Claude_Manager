# hwp-template-extractor

**양식을 사람이 옮겨 적지 않는다.** 원본 hwp를 파싱해 서식 규칙을 뽑아낸다.
결과물 `template.json`은 [`hwp-report`](../hwp-report/SKILL.md)의 렌더러가 그대로 읽는다.

```
양식.hwp ──extract_template.py──▶ template.json ──build_hwp.py──▶ 새 내용의 .hwp
              (이 스킬)              공유 계약서            (hwp-report 스킬)
```

계약서는 **하나뿐**이다: `hwp-report/schema/template.schema.json`.
추출기가 채우고 렌더러가 읽는다. 스키마에 없는 항목은 렌더러가 임의로 정하지 않는다.

## 전제

```bash
python -c "import hwp5, lxml; print('pyhwp/lxml OK')"    # 한글 프로그램은 필요 없다
```
없으면 `pip install pyhwp lxml`. (문서를 **만들** 때는 한글이 필요하다 — hwp-report 참조)

## 절차

### 1. 추출한다

```bash
python <this>/scripts/extract_template.py "양식.hwp" \
       -o ~/.claude/skills/hwp-report/templates/<양식이름>.json --name "<양식이름>"
```

출력되는 세 가지를 **반드시 읽는다**.

| 출력 | 무엇인가 | 어떻게 쓰나 |
|---|---|---|
| **추론 근거** | 각 항목을 무엇을 보고 그렇게 정했는지 (관측 횟수·실측 mm·색) | 사용자에게 확인받을 때 그대로 제시 |
| **신뢰도** | high / medium / low | `low`는 원본에서 근거를 못 찾아 기본값을 쓴 것 — **반드시 확인** |
| **미지원 요소** | 원본이 쓰지만 렌더러가 재현 못 하는 것 | 사용자에게 미리 알린다 (셀 병합·그림·다단 등) |

### 2. 애매한 항목만 확인받는다

`low`이거나, 근거에 "확인 필요"가 붙은 항목만 사용자에게 묻는다. 물을 때는 **근거를 붙여**
객관식으로 묻는다. 용지·여백·글꼴·색처럼 `high`인 항목은 묻지 않는다.

> 사다리 순서를 `□ → ∙ → → → -` 로 추정했습니다(루트는 가장 크고 굵은 `□`,
> 부모 관계는 `∙←□`, `→←∙`). 이 순서가 맞습니까?

확인받은 항목은 `confidence`를 `confirmed`로 바꿔 템플릿에 반영한다.

### 3. 라운드트립으로 검증한다 (이게 "양식을 맞췄다"의 근거다)

추출한 템플릿으로 **원본과 비슷한 내용**을 렌더해 원본 PDF와 나란히 본다.

```bash
python <hwp-report>/scripts/build_hwp.py <샘플doc>.json _rt.hwp -t <양식이름> --pdf _rt.pdf --kill-stale
python <hwp-report>/scripts/verify_hwp.py _rt.hwp --pdf _rt.pdf --png-dir _rt --json _rt/report.json
```
그리고 `hwp-doc-reviewer` 서브에이전트에게 **원본 페이지 이미지와 재생성 이미지를 함께** 보여
차이를 지목하게 한다. 원본에 매크로가 있으면 한글로 열 때 멈추므로, 원본 PDF는 사용자에게 받는다.

### 4. 차이가 있으면 **추출기를 고친다**

템플릿 JSON을 손으로 고치는 것은 그 문서에만 통하는 응급처치다. 다음 양식에서 같은 문제가
또 난다. **반드시 `extract_template.py`의 규칙을 고치고 다시 추출**한다.

## 추출 규칙 (일반 규칙으로만 쓴다)

특정 문서의 값을 코드에 박지 않는다. 지금 구현된 규칙:

| 항목 | 추론 방법 |
|---|---|
| 페이지 | `PageDef` 실측. 본문 폭 = 용지 − 좌우 여백 |
| 글꼴 | 문단 글꼴 사용 빈도 최빈값. 2종 이상이면 "혼용"을 미지원으로 보고 1종으로 통일 |
| 제목 구현 | **배너표 판정** = 2칸 · 3행 이하 · 첫 칸이 6,000 HWPUNIT 미만 · 첫 칸 내용이 번호. 아니면 문단 제목(`1.`/`가.` 패턴) 또는 **기호형 제목** |
| **기호형 제목** | 최상위 문단에서 같은 기호(❒ ■ 등)로 2회 이상, 본문보다 크고 굵게 시작하면 제목 후보. 단 **① 그 기호가 표/박스 안에서도 2회 이상 쓰이거나 ② 후속의 40% 이상이 하위 불릿이면 본문 불릿으로 판정** (제목은 셀 안에 살지 않고, 불릿은 자식을 거느린다) |
| 제목 레벨 배정 | 배너 종류를 글자 크기 내림차순으로 h1, h2에 배정. 남는 레벨은 문단 제목으로 |
| **사다리 순서** | 부모 = "바로 앞에 가장 자주 오는 기호". 루트 = 가장 크고 굵은 기호. 루트부터 트리를 내려가며 레벨 부여. 빈도 5% 미만 기호는 편집 노이즈로 제외 |
| 내어쓰기 | 기호 폭 ≈ 글자 크기 × 1.5, 2배 스케일 적용 (HWP_SCHEME.md 함정 #15) |
| **셀 장식** | 역할별(배너 번호/제목, 표 헤더/본문, 박스, 표지) 대표 셀의 `BorderFill`을 면별로 읽어 최빈값. **borderfill-id는 1-based** |
| **선으로 쓰인 얇은 행** | 높이 700 HWPUNIT(2.5mm) 이하인 행은 테두리가 아니라 '선'으로 본다. 위 행의 아래 테두리 / 아래 행의 위 테두리로 정규화. 두께 = 행 높이, 색 = 채운 색. 그 행에 1pt 잔여 텍스트가 있어도 선으로 취급 |
| 배경 최빈값 | 흰색(=없음)도 후보에 넣는다. 빼면 소수의 색칠된 셀이 양식 규칙으로 굳어버린다 |
| 셀 상하 여백 | 원본 실측. 한글 기본값(141)이면 글자가 괘선에 붙으므로 240까지 올린다 |
| 강조색 | 본문 글자색 중 검정·흰색 아닌 최빈값 |
| 표지 | 문서 첫 표가 1열이고 어느 행에든 텍스트가 있으면 `boxed` |

## 이 스킬을 고칠 때

**테스트 순서를 지킨다.**

1. 추출기를 원본에 돌린다
2. 출력이 원본의 사실과 맞는지 **원본 데이터로 대조**한다 (`hwp5`로 직접 확인)
3. 틀리면 **추출기 규칙을 수정**한다 — 템플릿 값을 고치지 않는다
4. 다시 1번

실제로 이 순서로 잡은 결함들: borderfill 0-based 오독, 얇은 선 행에 남은 1pt 텍스트 때문에
밑줄 정규화 실패, 흰색을 배경 후보에서 빼서 없는 배경이 생긴 것, 들여쓰기 기준 사다리 정렬 오류,
회의록 양식에서 ❒ 기호형 제목 미탐지·∎ 사다리 누락, □(불릿)를 제목으로 오인한 회귀(셀 안 사용 규칙으로 해소).

## 한계

- **셀 병합·그림·다단·가로 방향**은 추출은 감지해 보고하지만 재현되지 않는다(렌더러 미지원)
- 문단 왼쪽 여백은 원본에 편집 흔적이 많아 사다리 정렬 기준으로 쓰지 않는다
- 원본에 매크로(Script)가 있으면 한글로 열 때 멈춘다 — 이 스킬은 파일을 직접 파싱하므로 무관하지만,
  육안 대조용 PDF는 별도로 받아야 한다
