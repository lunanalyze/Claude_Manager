# HWP 문서 생성 구현 노트 — 일반 규칙 · COM 함정 · 검증

어느 조직의 양식이든 공통으로 성립하는 **일반 규칙(R)·한글 COM 함정·검증 방법**을 담는다.
이 문서의 목적은 하나다 — **LLM이 내용만 정하면, 형식은 규칙이 결정하게 만드는 것.**

> ⚠️ **양식별 수치(여백·색·계층 기호·표 스타일)의 단일 원본은 `templates/<양식>.json`이다**
> — `hwp-template-extractor` 스킬이 원본 hwp에서 추출한다. 아래 §1~§5에 남아 있는 구체 수치는
> 최초 분석에 쓴 견본 보고서(41개 표·868개 문단) 한 종의 **예시값**이며, 규칙의 의미를
> 설명하기 위한 것이지 어떤 양식의 표준도 아니다.

## 0. 절대 규칙 (위반 시 검증기가 FAIL)

| ID | 규칙 | 이유 |
|---|---|---|
| **R1** | 표 폭 ≤ **51,026 HWPUNIT (180mm)** | 본문 폭. 넘으면 오른쪽이 잘려 인쇄됨 |
| **R2** | **중첩표(표 안의 표) 금지** | 레이아웃 붕괴 1순위 원인. 레퍼런스에도 3개뿐이며 전부 편집 사고 흔적 |
| **R3** | 모든 표는 `쪽 경계에서 나눔` + `제목 줄 반복` 유지 | 표가 페이지를 넘을 때 헤더 없이 잘리는 것을 방지 (한글 신규 표 기본값이므로 건드리지 말 것) |
| **R4** | 데이터표 열 수 ≤ **8** | 9열 이상은 180mm에서 셀당 22mm 미만 → 줄바꿈 폭주 |
| **R5** | 계층 건너뛰기 금지 (`Ⅰ` 다음에 `1.`이나 `□`가 바로 오지 않음) | 목차 구조 붕괴 |
| **R6** | 글꼴은 문서 전체 **1종**(+ 폴백) | 레퍼런스의 나눔고딕/맑은 고딕 혼용은 붙여넣기 사고이지 의도가 아님 |
| **R7** | 강조색은 **파랑(#0000ff)** 하나만. 빨강 금지 | 빨강은 수정지시·오류로 읽힘 |
| **R8** | 셀 안에 빈 값 금지 — `-` 또는 `해당없음`을 넣는다 | 빈 셀은 "누락"으로 읽힘 |
| **R9** | `☞` 결론은 **44자 이내 1줄** | 파랑 굵게가 두 줄로 접히면 강조 블록이 커져 힘이 빠지고 꼬리 음절만 남는다 |
| **R10** | `pagebreak`는 꼭 필요할 때만 | 강제 개행 1개가 반 쪽을 비우고 뒤쪽에 2줄짜리 유령 페이지를 만든다. 페이지 배분은 내용량이 결정하게 둔다 |
| **R11** | 쪽 끝에 **제목·헤더만 남기지 않는다** | 배너만 남고 본문이 넘어가거나(고아 제목), 표 헤더 띠만 남고 데이터가 전부 넘어가면 절 경계에 `pagebreak`를 넣어 절 전체를 다음 쪽으로 보낸다. 헤더가 반복돼도 **데이터 0~1행짜리 잔여는 규칙 위반**이다 |
| **R12** | 제목 위 여백은 **h1 ≥ h2** | h1 대배너가 h2 소배너보다 위 여백이 좁으면 위계가 역전돼 두 제목이 한 덩어리로 읽힌다 |

## 2. 계층 사다리

레퍼런스에서 관측된 머리기호 사용 빈도(총 204회)에 근거한다.

| 레벨 | 기호 | 구현 | 크기 | 굵기 | 색 | 관측 |
|---|---|---|---:|---|---|---:|
| **H1** | `Ⅰ. Ⅱ. Ⅲ.` | **배너표**(2칸) | 14pt | 굵게 | 검정 | 11회 |
| **H2** | `1 2 3` | **배너표**(2칸, 번호칸 반전) | 12.5pt | 굵게 | 번호 흰색 / 제목 검정 | 12개 표 |
| **H3** | `1. 2. 3.` | 문단 | 11~12pt | 굵게 | 검정 | 32회 |
| **B1** | `□` | 문단 | 11pt | 굵게(86%) | 검정 | 29회 |
| **B2** | `∙` | 문단 | 11pt | 보통 | 검정 | 51회 |
| **B3** | `→` `↳` | 문단 | 11pt | 보통 | 검정/파랑 | 25회 |
| **B4** | `-` | 문단 | 9~10pt | 보통 | 검정 | 15회 |
| **결론** | `☞` | 문단 | 11pt | 굵게 | **파랑** | 7회 |
| **열거** | `① ② ③` | 문단 | 11pt | 보통 | 검정 | 9회 |
| **각주** | `*` `※` | 문단 | 9pt | 보통 | 검정 | 4회 |

### 들여쓰기 사다리 (내어쓰기 방식)

머리기호는 **내어쓰기(hanging indent)** 로 처리한다. 둘째 줄이 기호 아래로 흐르지 않고
텍스트 시작선에 맞아야 사람이 쓴 문서로 보인다.

한글 모델: **첫 줄 = 왼쪽여백, 둘째 줄부터 = 왼쪽여백 + |내어쓰기|**.
따라서 `내어쓰기 = -기호폭`으로 두면 둘째 줄이 텍스트 시작선에 맞는다.
단, 이 두 값은 **HWPUNIT의 2배 스케일**이다(함정 #15). 아래는 그 2배 값이다.

| 레벨 | 왼쪽 여백 | 내어쓰기 | 실제 렌더 |
|---|---:|---:|---|
| B1 `□` | 0 | -3,300 | 첫 줄 0mm, 둘째 줄 5.8mm |
| B2 `∙` | 3,300 | -3,300 | 5.8 / 11.6mm |
| B3 `→` | 6,600 | -3,300 | 11.6 / 17.4mm |
| B4 `-` | 9,900 | -2,850 | 17.4 / 22.4mm |
| 결론 `☞` | 3,300 | -3,300 | 5.8 / 11.6mm |
| 각주 `*` | 3,300 | -2,700 | 5.8 / 10.6mm |

줄간격 160%, 문단 아래 간격 소량. H1/H2 배너표 앞에는 빈 줄 1개.

## 3. 표 3종 — 역할이 다르면 절대 섞지 않는다

레퍼런스의 표 41개는 **배너 18 / 박스 10 / 데이터 13**으로 정확히 3종이다.

### 3-1. 배너표 (banner) — 제목 전용

`Ⅰ.`/`1` 같은 제목을 표로 그린다. **여기에 데이터를 넣지 않는다.**

- **H1 배너**: 2칸 `[번호 11mm][제목 나머지]`, 표 폭 = 본문 폭, 테두리 없음(위/아래 굵은 선만), 14pt 굵게
- **H2 배너**: 2칸 `[번호 6mm(진한 배경+흰 글자)][제목]`, 표 폭 ≈ 104mm(본문 폭보다 짧게), 12.5pt 굵게
- 셀 여백 상하 0.5mm, 좌우 1.8mm

### 3-2. 강조 박스 (box) — 결론·요약 전용

1행 1열 표에 `□`/`∙`/`→` 불릿을 담는다. 다음 상황에만 쓴다:

- 섹션의 **핵심 결론 3줄 이내**
- 표 바로 아래의 **해석 요약**
- 절차·기준의 **정의 블록**

테두리 실선 0.12mm, 배경 없음(또는 아주 옅은 회색), 셀 여백 좌우 1.8mm.

### 3-3. 데이터표 (data) — 수치 비교 전용

| 요소 | 규칙 |
|---|---|
| 헤더 행 | 배경 음영(#d9d9d9 또는 #e7e6e6), 굵게, **가운데 정렬**, 9~10pt |
| 본문 행 | 9~10pt. **숫자·금액·비율은 오른쪽 정렬**, 라벨은 왼쪽 또는 가운데 |
| 단위 캡션 | 표 **바로 위 오른쪽**에 `[단위 : 건, %]` (11pt 굵게) |
| 각주 | 표 **바로 아래**에 `*`로 시작, 9pt |
| 열 폭 | **가장 긴 셀 문자열이 한 줄에 들어가게** 배분한다. 숫자 열에 과대 폭을 주고 서술 열을 좁히는 것이 가장 흔한 실수 — 숫자 열은 `0.10~0.13`, 서술·비고 열은 `0.4` 이상이 보통이다. 합계 = 표 폭 |
| 셀 줄바꿈 | 수치가 `1,` / `234` 처럼 갈라지거나 단위 한 글자만 다음 줄로 떨어지면 열 폭 배분 실패다. 육안 검증에서 반드시 잡는다 |
| 병합 | **그룹 헤더 2단까지만** 허용. 본문 행 병합은 피한다 |
| 합계 행 | 맨 아래, 굵게, 라벨은 `합 계`(가운데 한 칸 띄움) |

### 3-4. 표로 뺄지 문장으로 쓸지 — 판단 규칙

이 판단이 "사람이 쓴 것 같은가"를 가른다.

| 상황 | 형식 |
|---|---|
| 같은 속성을 **3개 이상 항목**에 대해 비교 | 데이터표 |
| **시계열 4개월 이상** | 데이터표 (기간을 열로) |
| 항목 **2개 이하** 비교 | 문장 (`A 15건 → B 21건`) |
| 결론·시사점 **3줄 이내** | 강조 박스 |
| 조치 계획(담당·기한 포함) | 데이터표 (No/이슈/조치/담당/기한/상태) |
| 비교축 없는 서술이 3문장 초과 | 불릿 문단 (`□` → `∙`) |
| 수치 1~2개를 강조 | 문장 안에 굵게 + 파랑 |

## 4. 표지 블록

레퍼런스 1쪽 상단 구성:

1. 제목 — 1행 1열 표 안에 16pt 굵게 가운데 (표 폭 ≈ 151mm, 위아래 굵은 선)
2. 날짜 — `( 2026.07.31. )` 11pt 가운데
3. 부서 — `금융소비자보호부` 11pt 굵게 가운데
4. 빈 줄 1개 후 본문 시작

별도 표지 페이지를 만들지 않는다. **1쪽 상단에 제목 블록 + 곧바로 본문**이 이 양식의 특징이다.

## 5. 글꼴

| 용도 | 1순위 | 폴백 |
|---|---|---|
| 본문·표 전부 | **나눔고딕** | 맑은 고딕 → 함초롬돋움 |

> ⚠️ 한글 COM은 **설치되지 않은 글꼴을 지정하면 CharShape 적용 자체를 거부**한다(무시가 아니라 실패).
> 생성기는 시스템 글꼴 목록을 조회해 사용 가능한 첫 글꼴을 쓰고, 어떤 글꼴이 실제 적용됐는지 리포트한다.
> 최종 배포 PC(은행 단말)에 나눔고딕이 있다면 그 PC에서 생성하는 것이 가장 정확하다.

크기 분포(레퍼런스): 10pt 369회 · 11pt 235회 · 9pt 107회 · 12pt 33회 · 12.5pt 25회 · 14pt 16회 · 16pt 2회.
→ **본문은 11pt, 표는 9~10pt, 제목만 12pt 이상**이 기본선이다.

## 6. 한글 COM 구현 노트 (생성기가 반드시 지켜야 하는 것)

레퍼런스 재현 과정에서 실측한 함정들. `scripts/build_hwp.py`가 이대로 구현돼 있다.

| # | 함정 | 대응 |
|---|---|---|
| 1 | `PageSetup`이 조용히 실패(False) | `HSet.SetItem("ApplyClass", 24)` + `SetItem("ApplyTo", 3)` 를 반드시 함께 설정 |
| 2 | 표 `ColWidth`가 요청보다 **셀당 1,020 크게** 나옴 | ColWidth = 목표폭 − 1,020. 이 1,020은 **생성 시점 한글 기본 셀여백(510×2) 상수**이며, 양식 템플릿의 `padding_lr`(원본 문서의 셀여백)과 무관하다 — 템플릿 값을 빼면 폭이 어긋난다 |
| 3 | `WidthType=2`(단에 맞춤)면 ColWidth 무시 | `WidthType=0`(사용자 지정) + `WidthValue`=표 폭 |
| 4 | 미설치 글꼴 지정 시 `CharShape` 실패 → 크기·굵기까지 전부 미적용 | 글꼴 존재 확인 후 지정. 실패 시 글꼴 없이 재시도 |
| 5 | `win32com.client.gencache`가 깨져 Dispatch 실패 | `win32com.client.dynamic.Dispatch` (지연 바인딩) 사용 |
| 6 | 자동화 보안 경고 대화상자 | `RegisterModule("FilePathCheckDLL", "FilePathChecker")` 선행 |
| 7 | 표 생성 직후 커서 위치가 첫 셀이 아님 | `TableColBegin` + `TableColPageUp` 으로 좌상단 이동 후 채우기 |
| 8 | 표 뒤에 이어 쓰면 표 안에 갇힘 | 표 종료 후 `MovePos(2)`(문서 끝)로 표 밖으로 나온 뒤 문단 시작 |
| 9 | 문단 오른쪽 여백이 0이면 양쪽정렬 마지막 글자가 여백을 **약 1mm 침범** | 본문 문단에 오른쪽 여백 400 HWPUNIT 부여 (표·박스 내부 문단은 0 유지) |
| 10 | 셀마다 COM 호출 3~4회라 대형 보고서는 **수 분** 걸림 | 정상이다. 진행 로그를 stderr로 흘리고 백그라운드로 돌린다. 표 30개·6쪽 기준 약 8분 |
| 11 | 표 body의 `repeat-header=1`은 **파일 플래그일 뿐** — 실제로 헤더가 반복되지 않는다 | 헤더 행을 블록 선택한 뒤 `TablePropertyDialog` + `ShapeTableCell.Header = 1` 로 **'제목 셀' 지정**. `TableTitleCell` 등 액션 이름은 전부 False를 반환한다 |
| 12 | 앞선 실행이 남긴 한글 프로세스가 있으면 `Dispatch`가 **그 인스턴스에 붙어** 빈 문서 상태로 멈춘다(무한 대기) | 실행 전 `tasklist`로 확인하고 경고. 필요하면 `--kill-stale`. `Quit()`이 항상 프로세스를 끝내지는 않는다 |
| 14 | 기존 파일 경로에 `SaveAs` 하면 보이지 않는 덮어쓰기 확인 대화상자가 떠 **영구 대기**한다 | 임시 디렉터리에 저장한 뒤 `os.replace`로 교체. 이 증상은 렌더링이 100% 끝난 뒤 멈추므로 원인을 오해하기 쉽다 |
| 15 | `HParaShape`의 `LeftMargin`·`Indentation`은 **HWPUNIT의 2배 값**을 줘야 의도한 크기가 된다 | 실측: `left=1650` → 8.25pt만 적용. 문단 여백 계산은 전부 2배 스케일로. (표 폭·글자 크기는 정상 HWPUNIT) |
| 16 | 한글 줄나눔 기본값이 **글자 단위**라 `현금인출 22` / `건)` 처럼 수치와 단위가 갈라진다 | `HParaShape.BreakNonLatinWord = 0`(어절) · `BreakLatinWord = 0` 을 문단마다 설정 |
| 17 | 문단이 쪽 경계에서 갈리면 PDF 텍스트 추출 순서가 읽기 순서와 어긋나 검증기가 '내용 누락' 오탐을 낸다 | 검증 시 `page.get_text("blocks", sort=True)` 로 읽기 순서 정렬 후 대조 |
| 18 | 쪽 번호는 꼬리말(아래 여백)에 놓이므로 레이아웃 검사가 '여백 침범'으로 오탐한다 | 검증 시 `- 1 -` 형태의 쪽번호 패턴은 침범 검사에서 제외 |
| 19 | 셀 상하 여유를 늘리는 수단 중 **셀 안 여백(MarginTop/Bottom)·문단 아래 간격(NextSpacing)·줄간격 종류·셀 높이(Height)·세로정렬(VertAlign)은 전부 행 높이에 반영되지 않는다** (파일에는 기록되지만 렌더 무효) | 유일하게 동작하는 손잡이는 **문단 위 간격(PrevSpacing)**. 아래쪽 bbox 여백은 ~0.9pt로 고정되나 글꼴 디센더 영역이라 시각 여백은 그보다 크다 |
| 20 | 배너 글자색을 palette 공용값으로 쓰면 배경 없는 칸에 흰 글자가 들어가 **글자가 사라진다** | 글자색은 역할별 `cell_styles.*.text_color`(그 셀에서 추출한 값)를 최우선으로 |
| 21 | 빌드 중 **키보드 입력이 새어 들어가 셀 텍스트가 변조**될 수 있다 (예: '건당 평균' → 'x`당 평균ㅌ'). 자동화 창이 보이지 않아도 발생하며, PDF 읽기 순서 기반 검사로는 같은 문구가 다른 곳에 있으면 통과된다 | 생성 후 `verify_hwp.py`의 CONTENT 검사가 **표 셀을 문단 정확일치 + 필요 횟수(multiset)**로 대조해 잡는다. 빌드 중에는 해당 PC에서 타이핑을 피할 것 |
| 13 | 내어쓰기가 어긋나 둘째 줄이 머리기호 아래로 흐름 | 한글은 **첫 줄 = LeftMargin + Indentation, 둘째 줄부터 = LeftMargin**. 기호 폭(11pt 기준 1,650)을 LeftMargin에 더하고 같은 값을 음수 Indentation으로 상쇄해야 한다. `left < |indent|` 조합은 무효 |

## 7. 문서 모델 (doc.json)

LLM은 HWP를 직접 만들지 않는다. **의미 단위 JSON**을 쓰고 렌더러가 위 규칙대로 그린다.
스키마: [`../schema/doc.schema.json`](../schema/doc.schema.json)

```jsonc
{
  "meta": { "title": "...", "date": "2026.07.31.", "dept": "금융소비자보호부" },
  "blocks": [
    { "type": "h1", "num": "Ⅰ.", "text": "검토 배경" },
    { "type": "bullet", "level": 1, "text": "…" },              // □
    { "type": "h2", "num": "1", "text": "금융사기 신청건수 현황" },
    { "type": "box", "items": [{ "level": 1, "text": "…" }] },   // 결론 박스
    { "type": "table",
      "caption": "[단위 : 건, %]",
      "widths": [0.28, 0.18, 0.18, 0.18, 0.18],                 // 비율 또는 HWPUNIT
      "align":  ["center", "right", "right", "right", "right"],
      "header": [["구 분", "당월", "전월", "증감", "비고"]],
      "rows":   [["지급정지 등록", "15", "21", "-6", "2060"]],
      "note":   "* 집계 기준: 지급정지 등록일자" },
    { "type": "conclusion", "text": "…" },                       // ☞ 파랑 굵게
    { "type": "pagebreak" }
  ]
}
```

`type` 목록: `h1` `h2` `h3` `bullet`(level 1~4) `enum`(①②③) `conclusion` `note` `box` `table` `pagebreak` `spacer`

## 8. 검증 (생성 후 반드시)

`scripts/verify_hwp.py` + `agents/hwp-doc-reviewer.md` 서브에이전트가 4단계로 본다.

1. **구조 규칙** — 계층 순서, 머리기호 레벨, 표 열 수 일치, 중첩표 없음, 글꼴·크기 일탈, 빈 셀
2. **레이아웃 실측** — PDF 좌표로 표 bbox가 본문 영역을 벗어나는지, 표가 페이지 경계에서 잘리는지, 셀 텍스트 넘침
3. **육안 검증** — 페이지 PNG를 서브에이전트가 직접 보고 판정 (자동 규칙이 못 잡는 '보기 흉함')
4. **내용 정합** — 원본 md/데이터의 수치가 변환 중 손상되지 않았는지 대조

셋 중 하나라도 실패하면 doc.json을 고쳐 다시 생성한다. **hwp 파일을 직접 손으로 고치지 않는다** —
그러면 다음 생성 때 되돌아간다.
