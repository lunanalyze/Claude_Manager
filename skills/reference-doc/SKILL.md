# reference-doc

유용한 기능이 **어떻게 구현됐는지 + 어떻게 검증하는지**를 실제 코드 발췌와 함께 참고 문서로 남긴다.
결과물은 `Claude_Manager/docs/references/` 에 **한 패턴 = 한 파일**로 쌓인다.

`issue-log`와 짝을 이룬다:
- **issue-log** = "무엇이 안 됐고 어떻게 뚫었나"(실패·검증 사례).
- **reference-doc**(이 skill) = "유용한 기능을 어떻게 구현했나 + 어떻게 검증하나"(재사용 패턴).

## 무엇을 문서화하나 (선별 기준)
"해줘" 했을 때 **한 번에 되리라 확신하기 어려워 기능검증이 필요한** 비자명한 구현을 우선한다:
- 라우팅·API·데이터 흐름, **보안 가드**(경로 이탈·화이트리스트 등), 빌드/서버시점 주입,
  파싱(frontmatter·JSONL 등), 외부 연동, SSR/하이드레이션 의존, 상태 동기화(낙관적 업데이트 등),
  파일시스템·환경 분기 처리 등.
- **제외**: 단순 CRUD·보일러플레이트·설정 한 줄처럼 검증이 무의미한 것.

## 모드 선택

### 모드 A — 지정 (기본)
사용자가 **특정 기능**을 짚어 요청("이거 references로 정리", `/reference-doc`).
→ 대상 코드를 실제로 읽고 **참고 문서 1개**를 쓴다. 아래 [작성 절차].

### 모드 B — 스캔 (`scan` / "프로젝트 전체 훑어")
프로젝트 전반의 재사용 가치 있는 구현을 **백필**할 때. 대량 작업이므로 아래 순서.

1. **지형 파악**: 구조를 훑는다.
   ```bash
   git -C <repo> log --oneline | grep -iE "feat|fix" | head -60   # 기능 커밋이 후보
   find <repo> -type f \( -name '*.js' -o -name '*.jsx' -o -name '*.ts' -o -name '*.tsx' -o -name '*.py' \) \
     -not -path '*/node_modules/*' -not -path '*/.next/*' -not -path '*/.git/*'
   ```
   README·CLAUDE.md로 프로젝트 의도를 먼저 파악한다.
2. **후보 선별**: 위 [선별 기준]에 맞는 **비자명·검증필요** 구현만 고른다. 파일/모듈 단위로 묶는다.
3. **실제 코드 읽기(위조 금지)**: 각 후보의 핵심 흐름 파일을 Read로 읽어 "핵심 조각 + 왜"를 뽑는다.
4. **중복 배제**: `docs/references/` 와 `docs/issues/` 를 grep 해 이미 다룬 건 새로 만들지 않고 갱신한다.
   (issue로 남길 실패담은 여기 넣지 않는다 — 성격이 다르다.)
5. **분량이 크면 팬아웃**: 모듈이 많으면 모듈별 서브에이전트(Task/Explore)로 요약을 받아 취합한다.
6. 각 확정 패턴을 [작성 절차]로 **파일 1개씩** 남기고, 끝에 **스캔 요약**(훑은 범위, 만든 문서 수,
   건너뛴 이유)을 보고한다. 범위가 넓으면 먼저 "후보 N건 — 이걸로 정리할까요?"로 확인한다.

## 작성 절차 (두 모드 공통)

같은 폴더의 `TEMPLATE.md` 구조를 따른다. 원칙:
- **실제 코드만 발췌**하고 출처를 `파일경로:줄번호`로 인용한다. 전체 파일 덤프 금지 — 핵심만, 사이는 `// …`.
- **"왜 이렇게 했는가"**(대안 대비 선택·트레이드오프·함정)를 반드시 담는다.
- **검증 방법(How to verify)을 구체적으로** — 명령/입력과 **기대 출력**까지. 이 skill의 대상이
  "기능검증이 필요한" 것들이므로, 이 섹션이 비면 문서로서 미완이다.
- **검색 가능하게**: 제목은 기능 한 줄, `키워드`에 미래 세션이 칠 검색어. (references는 CLAUDE.md에
  자동 주입되지 않으므로 제목·키워드가 발견성을 좌우한다.)
- 참고(reference) 톤 — 강제 표준 아님. 프로젝트별 취사선택 여지를 남긴다.

## 저장·색인
- 경로: `Claude_Manager/docs/references/<slug>.md` (분류 늘면 `references/<domain>/`).
- `<slug>`: 내용을 드러내는 영문 kebab-case (예: `confined-fs-browse`, `selections-driven-tokens`).
- 색인: `docs/references/README.md` "목록"에 한 줄 추가 — `- [제목](./<slug>.md) — 한 줄 훅 · \`키워드\``.

## 보고
저장 경로, 핵심 결정 1–2개, **검증 한 줄**, 출처를 요약해 전달(스캔은 전체 요약 포함).

## 품질 체크 (저장 전 자문)
- 이 문서만 읽고 **다른 프로젝트에서 재현**할 수 있는가?
- 코드 발췌가 **실제 파일과 일치**하고 출처가 달렸는가?
- **검증 방법이 실행 가능**하고 기대 출력이 있는가?
- 6개월 뒤 세션이 **키워드로 검색해 도달**할 제목·태그인가?

## 설계 메모
- 단일 원본 `Claude_Manager/skills/reference-doc/`, 각 환경 `~/.claude/skills/`에 설치
  (WSL 심링크·Windows 복사 — `scripts/sync-*` 참고).
- 생성물(references)은 `docs/`(git 추적)라 WSL/Windows가 공유한다.
